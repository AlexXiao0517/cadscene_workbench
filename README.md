# CADScene Workbench

[English](README_EN.md) | 中文

CADScene Workbench 是面向建筑、道路等工程场景的本地视频与 CAD 协同工作台。它把现场视频、CAD 图纸、视频分析、片段轨迹、人工校准、工程信息标牌、渲染和项目合并组织在一个可恢复的项目流程中。

这里的 SfM（三维重建）指从视频画面估计相机运动与场景结构，再通过人工关键帧把相机轨迹对齐到 CAD。本文面向实际操作；部署、接口、存储和二次开发请从[文档中心](docs/README.md)进入。

## 适用场景与准备

适用于以现场视频核对建筑或道路设计、重建相机视角、将视频与 CAD 对齐、在成果视频中标注工程位置，以及在同一坐标系内迭代 CAD 图纸的项目。

开始前请准备：

- 一段清晰、连续的 MP4 现场视频。
- 与项目对应的 DXF 图纸。正式上传界面目前仅支持 MP4 视频和 DXF 图纸；后端兼容接口能接收的其他扩展名不等于当前界面已支持或已完成端到端验收。
- 可选的普通 SRT。它只提供时间、位置等元数据线索，不是高精度位置、姿态或 CAD 高程真值。若门户显示 Interface only（仅界面），请新建不上传 SRT 的项目或联系维护人员。
- 熟悉现场和图纸的人员，用于确认关键画面、CAD 位置和视场角（FOV）。

DXF 中的 `TEXT`、`MTEXT` 和块属性文字会随图层、位置、旋转和字号导入 CAD 视图；桩号和其他工程标注可以直接用于关键帧对齐参考。

## 快速开始

建议始终显式指定可写存储根，避免把人工项目和渲染产物写入代码目录。PowerShell 示例：

```powershell
New-Item -ItemType Directory -Force -Path D:\cadscene-work | Out-Null
python -m pip install .
cadscene-workbench doctor --storage-root D:\cadscene-work
cadscene-workbench serve `
  --bind 127.0.0.1 `
  --port 8300 `
  --storage-root D:\cadscene-work
```

浏览器首先进入项目库，可用卡片或列表重新打开现有项目，也可从“新建项目”进入上传页：

```text
http://127.0.0.1:8300/apps/project_library/
```

直接新建项目的上传入口：

```text
http://127.0.0.1:8300/apps/workflow_portal/
```

已知 `project_id` 时可直接进入项目片段管理：

```text
http://127.0.0.1:8300/apps/project_workspace/?projectId=<project_id>
```

`--root` 提供静态页面，默认是代码仓库根；`--storage-root` 保存项目数据，服务会在其中使用 `projects/`。省略 `--storage-root` 时，存储根继承 `--root`，因而会在代码目录中创建 `projects/`。正式测试和长期使用应显式指定独立目录，并在每次重启时保持一致。

## 当前工作流状态

| 工作流或能力 | 状态 | 边界 |
|---|---|---|
| `sfm_only` | Stable（稳定） | 当前稳定的端到端主路径：视频分析、片段管理、SfM、人工对齐、质量检测、渲染和合并。 |
| `pure_rotation` | Supported（正式支持） | 固定相机中心的旋转恢复、全局放置、局部校正和渲染已进入正式流程；依赖固定版本外部 OpenGV 后端。自动场景判断仍需人工复核。 |
| partial-SRT core | Experimental CLI | 提供 PTS、ENU 和稳健 Sim3 融合核心，尚未接入正式项目任务队列。 |
| `srt_sfm_fused` / `srt_full_pose` | Interface only | 门户可识别并提示，正式阶段启动仍被阻止。 |
| SfM CUDA | Optional（可选） | 只确认受支持的特征提取和匹配；建图与全局 BA 不应描述为 GPU 处理。 |
| CAD 锚定工程标牌 | Supported | 在 CAD 中选择世界坐标，预览和正式渲染按当前有效相机轨迹投影。 |
| 视频目标跟踪标牌 | Hidden baseline | 后端与历史数据兼容保留，但当前界面隐藏创建入口，不作为正式可用功能。 |

上传页不再要求用户预先选择“旋转模式”。未上传 SRT 或未形成 SRT 界面路线时，系统会自动检测运动特征并保守推荐 `sfm_only` 或 `pure_rotation`；对这两条可执行路线，项目片段管理页显示推荐值，并通过只含 SfM/OpenGV 的“最终工作流”下拉框采用或覆盖它。若 SRT 分析产生 Interface-only 推荐，推荐列会显示该路线，而下拉框可能回显 SfM 但不代表覆盖已保存；当前不能依赖这个回显把同一项目转为稳定流程，应新建不上传 SRT 的项目。自动推荐只是路线选择，不是精度证明，普通 SRT 也不能替代 SfM、人工校准、SfM-CAD 对齐或质量检查。

## 从上传到项目交付

1. 在上传门户创建项目，选择视频、CAD 和可选 SRT。服务先保存不可变输入，再异步完成视频分析、场景切分、片段导出和 CAD 导入。
2. 进入“项目片段管理”，检查系统自动检测的运动模式和推荐工作流；最终工作流下拉框只提供 SfM 与 OpenGV。通常直接使用对应推荐值，判断与现场不符时再人工覆盖。Interface-only 的 SRT 推荐不能靠下拉框回显的 SfM 直接转为稳定流程；需要稳定流程时新建不上传 SRT 的项目。可对选中片段批量轨迹反算、批量渲染，也可逐片段进入工作台。
3. `sfm_only` 片段先运行 SfM；在关键帧标定中至少保存两个有效人工关键帧并执行路线拟合，再生成关键帧计划、补充标定和完成最终拟合。
4. 运行质量检测；通过后点击“完成质量检测”进入渲染导出。若需要补帧，返回关键帧标定继续处理。
5. 在渲染导出阶段可添加 CAD 锚定工程标牌，也可直接无标牌渲染。点击“渲染视频”后，当前标签状态会随输入指纹进入不可变渲染 revision。
6. 返回项目片段管理，确认所有需要交付的片段已有当前有效渲染，再执行“合并输出”。合并严格使用每段 `render_frame_map.json` 的 source PTS 分区，不能重复或遗漏帧。
7. 刷新页面或重启服务后，使用相同 `--storage-root` 和 `project_id` 重新进入；已保存工作台输出、标签、任务、渲染和版本历史会从项目 manifest 恢复。

`pure_rotation` 使用“开始运行—全局放置—局部姿态校正—渲染”步骤，跳过标准 alignment/quality 路径；它固定相机中心，因此不适用于恢复沿道路行进距离。当前不成熟的是自动视频分析与路线推荐精度，而不是纯旋转执行流程本身。

## CAD 文字与工程信息标牌

CAD 原图文字和用户创建的工程标牌是两类不同内容：

- CAD 原图文字来自 DXF，显示在右侧 CAD 三维场景中，用于识别桩号和工程标注。大型图纸会按可见性和显示预算控制文字数量，避免明显影响相机拖动。
- 工程标牌由屏幕空间信息卡片、折线引线和圆形锚点组成。卡片包含标题和多行正文，始终朝向屏幕，不随 CAD 平面倾斜。
- 暂停视频后选择“CAD 锚定”，在右侧 CAD 场景点击位置即可创建。拖动卡片只修改相对锚点的 `screen_offset`，不会移动真实 CAD 坐标。
- 播放或 seek 时，锚点随当前 Base/Corrected 有效相机轨迹重新投影；锚点位于相机背后、出画、轨迹无效或超出显示 PTS 范围时，卡片、引线和锚点会一起隐藏。
- 修改标题、正文、样式或偏移只会让当前片段渲染结果 stale，不会重跑相机轨迹。没有标牌时继续走原有快速渲染路径；存在标牌时会烧录进 `rendered.mp4`。

正式同步以 source decoded-frame integer PTS 和精确 `time_base` 为权威，不使用 `currentTime × fps` 或固定 FPS 帧号反推源帧。

## 全局替换 CAD

已至少保存一个有效工作台输出、证明项目坐标系已经打通后，项目 CAD 卡片右侧会提供悬停式“替换”入口：

当前正式验收和用户支持口径仍以 DXF 为准。替换对话框为迁移保留的其他兼容文件筛选项，不代表这些格式已经完成正式端到端验收。

1. 选择新版 DXF，并勾选“新版 CAD 与当前项目使用相同坐标系”。
2. 服务把新版图纸作为候选版本导入和校验；进度达到发布阶段前，旧 CAD 始终保持活动。
3. 成功后全项目切换到新版 CAD，保留既有片段、SfM、轨迹、关键帧和工作台输出，只把依赖 CAD 的渲染与最终合并标记为 stale。
4. 重新进入片段工作台检查新版图纸，可直接微调并重新渲染，无需重新做初始标定和路线拟合。
5. 替换失败时继续使用旧 CAD，并保留错误和 CAD 版本历史供排查。

如果新版 CAD 改变了坐标系、单位或原点，不要使用该入口；应创建新项目并重新标定。服务重启时会使用原始分析的不可变输入快照验证旧分析任务，再绑定当前 CAD 项目契约，不会因为合法替换而重跑分析或误判整个项目失效。

## 常见问题

### 为什么任务显示 pending 或进度短暂停留？

项目任务使用本地资源队列。`pending` 表示等待依赖或资源槽，不等于算法已经启动；进度只有在准备、计算、结果校验和发布阶段都完成后才到 100%。请以项目页阶段文字、任务运行详情和服务日志共同判断。

### 处理需要多久？

取决于视频长度、图像质量、硬件和工作流。视频分析、SfM、渲染和发布是不同阶段；不要只用动画或单次百分比推断整个任务完成。

### 需要 GPU 吗？

不需要。默认使用 `pycolmap + CPU`。CUDA 必须显式选择并通过能力检测，且只覆盖确认支持的特征提取和匹配。

### FOV 不一致或对齐不正确怎么办？

优先复核彼此一致的人工关键帧 FOV、CAD 锚点、比例和原点。FOV 本身不能保证 SfM 准确；必要时回到关键帧阶段补充或修正锚点。

### 刷新后为什么会话失效？

工作台编辑会话是带令牌的临时写权限；已保存输出才是持久结果。若会话失效，请从同一项目片段管理页重新点击“进入工作台”，不要复用旧 token URL。刷新项目页不会删除已保存输出。

## 能力边界

- `sfm_only` 是当前稳定主路径；SRT 融合和 full-pose 尚未形成正式端到端流程。
- `pure_rotation` 是正式支持的固定相机中心路线；自动视频分析与路线推荐仍需人工复核。partial-SRT 和视频目标跟踪标牌仍是实验性或隐藏能力。
- CAD 锚定标牌不承诺真实视频中的物体遮挡推理；当前只处理相机前后、画面范围和时间范围。
- 不支持跨片段自动跟踪、跨场景标签继承、语义识别或大型神经跟踪模型。
- 结果必须由熟悉现场和设计意图的人员复核；实验性能力不能替代工程测量或专业验收。

## 存储、结果与排障

当前项目数据位于 `<storage-root>/projects/<project_id>/`，包括五类领域 manifest、不可变分析/工作台/渲染输出和任务尝试目录。旧版 `<storage-root>/data/` 与 `<storage-root>/runs/` 只服务兼容工作流或历史资产，不是新项目领域的主存储位置。

不要手工修改 manifest、移动单个 revision 或复制活动工作台 token。出现上传、恢复、任务、CAD、标牌、渲染或合并问题时，先保留 `project_id`、`clip_id`、任务 ID、项目快照和对应日志，再查阅[故障排查](docs/technical/troubleshooting.md)。
