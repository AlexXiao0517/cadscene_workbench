# 周复盘：2026-07-06 至 2026-07-12

## 本周结论

本周最重要的进展不是单个功能上线，而是把 SfM-CAD 项目推进到可实操完善的工作流：从 SfM 重建、关键帧标定、SfM-to-CAD 对齐、质量评估，到 Web Viewer 复核，逐步形成“运行—检查—补锚—重新对齐—再评估”的闭环设计。

当前后端模块基本具备，但首轮端到端闭环尚未跑通：双关键帧标定后的无人机路径拟合还没有接入前端实际运行，因此前端质量判断也尚未完成测试。

## 本周完成的工作

1. 完成工作台化迁移与流程整理。
   - 建立 `cadscene` 包、CLI、配置化 pipeline 和 `runs/<dataset>/<run_id>/` 产物布局。
   - 将旧 `project/` 作为迁移参考，减少新流程对旧脚本和旧输出路径的依赖。

2. 补齐 SfM-CAD 工作流的核心环节。
   - 增加 SfM 重建、CAD 对齐、质量评估、道路表面诊断、Viewer 场景导出和 overlay 渲染能力。
   - 增加质量时间线与关键帧建议，使问题定位不再只依赖最终叠加视频。

3. 推进 Web Viewer 从结果查看走向工作流节点。
   - 增加任务运行、状态查询和对应前端界面。
   - 前端与后端模块尚未完成首次完整接通和实跑验证。

## 关键判断

- 两个坐标系的打通不能只靠单帧微调；至少需要两个关键帧标定作为初始约束。
- 质量检测不是一次性产出报告，而应在关键帧之间反复检查，决定是否补锚并重新对齐。
- 当前项目的主要风险不在“模块是否已写”，而在“模块能否按真实数据和前后端链路完整闭环”。

## 当前边界与未完成项

- 双关键帧标定后的无人机路径拟合后端已具备，但尚未接入并在前端跑通。
- 因路径拟合未实跑，前端质量判断尚未测试；不能将质量闭环表述为已完成。
- 1 分钟 `hygs` 视频的 SfM 重建约需 45 分钟，当前迭代成本较高。

## 下周优先事项

1. 接通双关键帧标定后的路径拟合前后端链路，完成一次真实数据实跑。
2. 在此基础上验证前端质量判断、关键帧建议和重新对齐闭环。
3. 降低初始关键帧标定成本，优先优化虚拟相机的初始定位或保存可复用初始位姿。
4. 调研并评估 GPU 版 COLMAP，以缩短 SfM 重建时间。
