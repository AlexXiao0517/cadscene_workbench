# 问题复盘：2026-06-22 至 2026-07-05

## 1. CAD bulge 圆弧被当成直线

现象：hygs 的中心线/边线在 CAD 中是弯道，但叠加后呈现折线或直线段，弯道形态丢失。

原因：LWPOLYLINE 带 bulge 圆弧参数，早期提取时只读取顶点 `(x, y)`，没有把 bulge 展开为圆弧采样点。后续 densify 只能加密已有弦线，不能还原圆弧。

解决方式：先做 `hygs_bulge_check` 对比确认问题；后续应在 DXF 解析层展开 bulge，再导出 road JSON。

下次检查项：遇到 LWPOLYLINE 必查 bulge；导出前看曲线预览；弯道路段至少抽样检查 CAD 原图、JSON 预览、overlay 三者是否一致。

## 2. CAD 窗口用 `camera_s` 导致前飞时滞后

现象：相机脚下 station 还在起点附近，但画面中远处道路已经向前推进，导致匹配窗口跟不上画面。

原因：斜视前飞时，“无人机在哪”不等于“画面里看到哪段路”。用相机地面投影点直接裁 CAD，会选错窗口。

解决方式：改为 visible-window：用相机视锥反投影估计 `visible_s_near / visible_s_far / visible_s_center`，再扩 margin 作为 CAD 匹配窗口。

下次检查项：日志中同时看 `camera_s`、`visible_s_center` 和 `match_window`；如果画面推进但窗口不动，优先查 visible range。

## 3. 场景二旧路线缺少绝对约束，长视频漂移

现象：关键帧附近能贴合，但离关键帧越远越不稳，出现抖动、提前/滞后、局部误匹配。

原因：无 SRT 条件下，旧路线主要靠 LK 和局部 ROI 外推相机 pose。没有 GPS/yaw 这样的逐帧绝对基准，也没有足够多关键帧锚点，误差会累积。

解决方式：路线切换到 SfM 3D 骨架：先用 SfM 得到真实相机运动，再用关键帧做 SfM 世界到 CAD 世界的相似变换和分段锚定。

下次检查项：不要把单帧贴合当成整段成功；至少检查关键帧之间、转弯处、立交处、远离锚点处。

## 4. ROI 过窄会造成局部看似对齐

现象：局部窗口里 center/edge 看起来能对上，但完整 CAD 或远处道路明显不对。

原因：ROI 太窄时，LK 和 Chamfer 分数只看到了局部纹理；斜视透视下远处线段容易在屏幕空间“差不多”，但沿程实际错位。

解决方式：引入更长的 visible station window、质量评估、多区域采样和关键帧建议；完整 CAD 作为诊断视图保留。

下次检查项：局部对齐后必须看完整 CAD、远近景分区、station 连续性和 quality timeline。

## 5. semantic refine 一度让结果变差

现象：`out/hygs1min_sfm_refine_v2` 的 semantic refine 结果全程漂移，已标记为 deprecated。

原因：基线已经足够贴合，refine 可优化空间小；Chamfer 目标不稳定，修正量频繁顶到上限，平滑后变成全局漂移。

解决方式：当前不采用 semantic refine，成品优先使用 `out/hygs1min_sfm_align_v2`。质量评估只读不改轨迹，不重启 refine。

下次检查项：任何 refine 模块上线前必须和基线 overlay 对比；看是否只是关键帧局部变好但全局变差；产物若废弃必须写 `DEPRECATED.md`。

## 6. Web Viewer 不能用普通静态服务替代

现象：大视频跳帧失败、播放后 seek 回到第 0 帧、页面连接异常。

原因：普通 `http.server` 对大 MP4 的 HTTP Range 支持不足，不能满足 Web Viewer 的跳帧和长视频调试。

解决方式：使用 `python -m cadvideo.pipeline.serve_web_viewer --port 8300 --bind 127.0.0.1`，并优先导出 1 分钟短片段调试。

下次检查项：Web 调试前确认服务是 `serve_web_viewer`；视频卡顿时先看 Range 服务和片段大小，不先怀疑前端逻辑。

## 7. 项目过程产物多，最终版本容易混淆

现象：`out/`、`archive/`、`data/`、`tmp_cadvideo/` 中有大量试验产物，容易拿错 track、alignment 或 refine 版本。

原因：实验推进快，但命名和归档说明没有同步跟上；git 仓库也暂无提交记录，无法用提交历史还原过程。

解决方式：新增 `organize_project_outputs.py` 和本 SOP；建议把当前推荐版本写进成果库和 README。

下次检查项：每次形成可演示版本，都记录“输入、命令、输出目录、是否推荐使用、废弃目录”。
