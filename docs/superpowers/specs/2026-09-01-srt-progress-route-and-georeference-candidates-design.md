# SRT 解析进度、全姿态路由与坐标候选交互设计

## 背景与目标

现有项目已能解析 DJI SRT、识别 `srt_full_pose`、确认 CGCS2000 CAD 地理参考，并在用户提供水平 FOV 后跳过 SfM 生成米制相机轨迹。本次增量解决三个用户可见问题：

1. 新建项目进度没有明确展示 SRT 解析；
2. 完整姿态 SRT 与“`SRT + 三维重建`”的关系不清楚；
3. 全姿态配置界面没有中央经线输入，坐标候选生成也没有真实进度。

目标是让上传 CAD、视频和 SRT 的用户从新建项目开始就能理解系统正在做什么、为何选择某条路线，并能输入例如 `120°` 的 CGCS2000 中央经线来生成可核验的候选。水平 FOV 与中央经线必须始终是两个不同参数。

## 用户流程

1. 用户在项目库上传 CAD、视频，并可选上传 SRT。
2. 新建项目进度固定显示“上传文件、解析 CAD、解析视频、初始化工作台”；仅在本次项目含 SRT 时插入“解析 SRT”。
3. 视频分析先建立权威 PTS 和片段区间，再解析 SRT 并按片段计算 GPS、高度、云台 yaw/pitch/roll 与完整姿态联合覆盖率。
4. 完整姿态联合覆盖率达到现有 80% 阈值时自动推荐 `SRT 全姿态`，明确显示“跳过三维重建”。只有位置可用但云台姿态不完整时才显示 `SRT 定位 + 三维重建（实验）`。
5. 用户进入全姿态配置，填写水平 FOV、CGCS2000 中央经线和可选 CAD 高程修正。
6. 用户点击生成候选；界面展示真实后台阶段和进度，完成后显示 EPSG、分带、轴映射、评分与轨迹落图预览。
7. 用户显式确认候选，再保存全姿态配置并进入现有轨迹工作流。

## 解析进度架构

### 不新增重复的 SRT 分析任务

SRT 的片段级能力判断依赖视频分析先产生的权威 PTS 和片段区间，因此不新增第三个独立 `srt_analysis` 队列任务。`video_analysis` 继续拥有解析与推荐结果，只增加显式进度阶段：

- `segmenting`：规划视频片段；
- `parsing_srt`：读取 SRT 并计算总体能力；
- `routing_clips`：计算各片段覆盖率与推荐路线；
- `publishing`：发布分析结果。

`parsing_srt` 在开始时报告阶段但不伪造内部百分比；完成后进入 `routing_clips`，前端将“解析 SRT”标记为 100%。SRT 文件很小时允许该阶段快速完成，但完成状态仍保留在后续界面状态中。

### 新建项目进度的条件渲染

前端根据项目已发布的 source asset 是否包含 SRT 决定是否插入该行，不能仅依赖浏览器中尚未释放的 `File` 对象。刷新或短暂断线后仍必须得到相同阶段列表。

总体进度按当前可见阶段重新归一化：

- 无 SRT：沿用上传、CAD、视频、工作台四段；
- 有 SRT：视频分析总权重拆分为“解析视频”和“解析 SRT”，其他权重不变；
- 任一后台阶段没有可证明的 fraction 时，使用不确定进度动画，不显示虚构数值；
- 后续阶段已经开始时，前序阶段必须显示完成，避免快速阶段因轮询未命中而永远停留在 0%。

## 路由语义与解释

现有能力阈值继续作为唯一后端真值：GPS、高度、云台 yaw/pitch/roll 以及同一记录上的 full-pose joint coverage 均达到 80%，推荐 `srt_full_pose`；位置/高度足够但完整云台姿态不足时推荐 `srt_sfm_fused`；其余使用现有 SfM 或纯旋转规则。

界面文案统一为：

- `srt_full_pose`：`SRT 全姿态（跳过三维重建）`；
- `srt_sfm_fused`：`SRT 定位 + 三维重建（实验）`；
- `sfm_only`：`三维重建`；
- `pure_rotation`：沿用现有纯旋转名称。

项目片段和配置弹窗展示覆盖率摘要与推荐原因，至少包含 GPS、高度、云台姿态和联合完整姿态覆盖率。完整 SRT 不得被前端降级显示为 `srt_sfm_fused`。若实际 SRT 字段缺失或覆盖率不足，则明确指出缺失项，而不是暗示系统忽略了完整姿态。

## 水平 FOV 与中央经线

配置弹窗新增 `CGCS2000 中央经线（°）` 数值输入，并在相邻说明中区分：

- 水平 FOV，例如 `72°`：相机镜头参数；
- 中央经线，例如 `120°`：CAD 平面投影参数。

中央经线允许留空以使用 SRT 经度自动推荐；用户填写后，候选器只评估 CRS 元数据中中央经线与输入一致的 CGCS2000 高斯—克吕格 EPSG 候选，再展开可能的 CAD X/Y 轴映射。输入必须是有限且位于 `-180°` 到 `180°` 的数值；如果 PROJ 数据库中没有匹配候选，返回可操作错误，不构造无法审计的自定义投影字符串。

中央经线只是候选筛选条件，不自动确认坐标系。`120°` 仅属于当前项目输入，不作为其他 CAD 的全局默认值。

## 坐标候选后台任务

### 任务契约

候选生成采用现有持久化项目队列，新增项目级 job type `cad_georeference_candidates`。任务不绑定 clip，输入指纹包含：

- 项目 ID；
- 当前 CAD 资产指纹及原始 bbox；
- 当前 SRT 资产指纹；
- 用户输入的中央经线或 `auto`；
- 候选数量上限；
- 候选算法版本。

相同输入复用正在运行或已成功的任务；任一输入变化都会产生新指纹，旧结果保留审计记录但在 snapshot 中标记 stale，不能继续确认。

`POST /api/projects/{project}/cad-georeference/candidates` 接收 `central_meridian_deg` 和项目 revision，幂等创建或复用任务并返回 `202` 状态。`GET` 同一路径返回当前输入对应的任务状态、进度、错误和完成候选。确认 API 继续保持独立的显式用户操作。

### 真实进度阶段

任务只报告可证明的进度：

1. `validating_inputs`：验证 CAD/SRT 指纹、bbox 与 GPS 样本；
2. `enumerating_crs`：从 PROJ 数据库枚举并按中央经线筛选 CRS；
3. `scoring_candidates`：逐个投影、展开轴映射并评分，fraction 来自已处理候选数/总候选数；
4. `building_previews`：整理落图折线、bbox 和评分证据；
5. `complete`：原子发布候选结果。

没有确定总量的阶段使用不确定进度动画。禁止用定时器递增或把请求等待时间伪装为计算百分比。

### 产物与恢复

任务 attempt 中原子写出 `cad_georeference_candidates.json`，内容包含 schema version、输入指纹、请求参数、候选、生成时间和算法版本。队列保存当前 stage、message、fraction 与失败信息，因此关闭并重新打开弹窗后可恢复展示。应用重启后沿用现有未完成任务恢复语义；损坏或指纹不匹配的产物不得暴露为可确认候选。

## 前端状态

全姿态弹窗增加：

- 覆盖率与推荐路线摘要；
- 中央经线输入；
- 候选任务阶段文本、进度条和百分比/不确定状态；
- 失败后的“重新生成”操作；
- 完成后的候选卡片和预览。

打开弹窗时先读取当前候选任务；若状态为 queued/running 则恢复轮询，若 success 且指纹仍匹配则直接恢复结果。候选运行时禁用中央经线输入与重复提交；失败时保留输入值和上一次已成功但明确标为旧版本的结果。

确认候选后，修改中央经线、替换 CAD 或替换 SRT 都会使确认和候选失效。只修改水平 FOV 或 CAD 高程修正不会使地理参考确认失效，但会继续使依赖配置的轨迹按现有规则 stale。

## 错误处理

- SRT 解析失败：新建项目进度显示失败原因，分析任务失败，不静默回退到 full pose；
- SRT 不完整：项目仍可打开，但展示覆盖率缺口并使用对应推荐路线；
- 中央经线非法或没有对应 EPSG：候选任务失败并显示明确输入错误；
- PROJ 环境缺失、CAD bbox 无效、SRT 无 GPS：候选任务失败且不覆盖上一次有效结果；
- revision 冲突：返回冲突并要求刷新快照，不用旧资产启动任务；
- 任务输出损坏或输入指纹过期：标记 stale/invalid，禁止确认。

## 测试与验收

后端测试覆盖：

- `video_analysis` 在有 SRT 时依次报告 `parsing_srt` 与 `routing_clips`；
- 完整 DJI SRT 推荐 `srt_full_pose`，部分云台姿态才推荐 `srt_sfm_fused`；
- 指定 `120°` 时只保留中央经线匹配的可审计 EPSG 候选，留空时保持自动推荐；
- 候选任务的真实阶段、分数进度、幂等复用、失败、重试、revision 与指纹失效；
- 损坏或 stale 候选不能被确认。

前端静态与浏览器测试覆盖：

- 无 SRT 项目不显示解析 SRT 行，有 SRT 项目显示；
- 快速完成或刷新后 SRT 行仍正确显示 100%；
- 完整姿态标签为“SRT 全姿态（跳过三维重建）”；
- FOV 与中央经线字段同时存在且请求参数互不混淆；
- 候选进度可从 queued/running 恢复，完成后显示候选，失败后可重试。

最终验收从项目库新建项目开始，上传 CAD、视频和 SRT，观察条件进度与 full-pose 推荐，填写水平 FOV 和中央经线，观察候选真实进度，确认坐标系并保存配置。

## 本次不做

- 不改变 `srt_full_pose` 的 80% 能力阈值；
- 不实现 `srt_sfm_fused` 的生产执行，只保留实验路线说明；
- 不把 SRT 解析拆成重复读取文件的独立队列任务；
- 不自动确认中央经线、EPSG 或轴映射；
- 不新增 FOV 类型、镜头型号库或 DJI 产品自动识别；
- 不用自定义无 EPSG 投影字符串绕过 PROJ 数据库校验。
