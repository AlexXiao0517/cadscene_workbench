# SRT 整视频单场景与单锚点姿态设计

## 目标

当项目包含可解析的 SRT 时，默认把完整视频视为同一个逻辑场景，不再因为视频超过一分钟而切成多个片段。对于只有位置、高度而没有云台/机身姿态的 SRT，位置严格采用 SRT→CAD 轨迹，视觉只恢复相对姿态；自动绝对锚定失败时，由用户在系统推荐帧校准一次 yaw、pitch、roll，并将该绝对姿态传播到同一连续视觉段。

## 已确认约束

- SRT 存在且可解析时，完整视频默认只生成一个逻辑片段。
- 不再对 SRT 工作流应用 45～60 秒时长分割，也不应用镜头场景边界分割；检测结果可以继续作为诊断信息保存。
- 没有 SRT 的 `sfm_only`、纯旋转等既有流程保持原分段行为。
- 视频与 SRT 仍以解码帧 PTS 为唯一时间权威，不使用 `frame / fps` 代替同步。
- SRT→CAD 的每帧 XYZ 是不可变基线；视觉不得反算或逐帧修改位置。
- 用户只输入水平 FOV，并且工作台只允许姿态编辑；整条路线 XYZ 偏移仍只能通过已有统一偏移设置修改。
- 固定轨迹流程不生成点云，也不进入质量检测阶段。

## 分析与场景产出

视频分析继续执行稀疏采样、镜头边界检测和运动诊断，但在有 SRT 输入时，逻辑片段规划改为一个覆盖 `[source_start_pts, source_end_pts_exclusive)` 的整视频片段。该片段的开始原因固定为 `source_start`，结束原因为 `source_end`，`scene_index=1`、`segment_index=1`。

SRT 解析后仍计算位置覆盖率和姿态字段覆盖率。SRT 解析失败应让分析失败并给出明确错误，不能静默退回 SfM 分段。完整视频只有一个片段，因此项目库、配置弹窗、轨迹任务和工作台都使用同一条完整源时间轴。

## 视觉相对姿态

视觉求解继续使用抽样帧的 ORB 匹配、Essential Matrix 和 `recoverPose`。求解结果拆为两层：

1. 相对姿态层：每个连通视觉段保留以该段首个有效帧为局部坐标原点的 `camera_from_visual_local` 旋转，即使 SRT 航线过直、视觉平移方向不一致而无法自动确定世界朝向，也不能丢弃这些旋转。
2. 绝对姿态层：现有 SRT 基线方向自动锚定成功时，继续直接输出世界姿态；失败时输出 `relative_only`，等待人工绝对锚点。

每个相对姿态帧带 `visual_component_id`。系统在最大连通段中选择匹配支持度最高的内部帧作为 `recommended_anchor_frame`，同时输出对应源 PTS、视频时间和相对姿态覆盖率。无有效视觉对时仍保持 `position_only`，不虚构推荐帧。

## 单锚点传播

用户在推荐帧调整 yaw、pitch、roll 并保存一个人工关键帧。对锚点所在视觉段：

```text
R(world<-local) = R(world<-camera_manual) × R(camera_anchor<-local)
R(world<-camera_frame) = R(world<-local) × R(local<-camera_frame)
```

该常量绝对旋转把整个相对姿态段映射到 CAD 世界坐标系，向锚点前后传播。SRT 中心保持原值，只叠加既有的整路线统一 XYZ 偏移。

如果用户增加第二个姿态锚点，则计算第二锚点相对单锚点预测的角度残差：残差不超过 5° 时保留单一常量校正；超过 5° 时在两个锚点之间对世界校正做 SLERP，并在两侧使用最近锚点校正，同时在结果中标记 `drift_corrected=true`。没有视觉连通关系的时间范围继续显示位置轨迹，但不显示相机视锥。

## 工作台交互

固定轨迹工作台新增独立的“姿态锚定”面板：

- 展示 SRT 位置覆盖、视觉相对姿态覆盖和当前已确认锚点数。
- 有推荐帧时显示“跳到推荐帧”，点击后按权威 PTS 定位视频和轨迹标记。
- 用户调整 yaw、pitch、roll 后点击“确认姿态锚点”，复用现有人工关键帧持久化接口。
- 一个有效锚点即可启用“应用姿态并进入渲染”；不再沿用普通 SfM 至少两个关键帧的限制。
- 无相对姿态时明确提示“视觉相对姿态不可用，不能通过单锚点传播”，而不是“SfM 参数不可用”。
- 轨迹始终显示。当前时间没有绝对姿态时隐藏视锥并显示“位置可用，姿态待锚定”。
- 首次进入从整视频轨迹起点开始；存在恢复状态时继续沿用恢复位置，但页面明确提供“回到轨迹起点”和“跳到推荐帧”。

固定轨迹工作台不得请求 `02_sfm/camera_trajectory.json`，相关状态文案不得出现 SfM、点云或质量检测。

## 数据兼容

轨迹 JSON 保留现有 `poses`、`center`、`orientation_available` 和绝对四元数字段。新增字段仅用于相对姿态：

- pose: `visual_component_id`、`cam_from_visual_local_quat_wxyz`
- meta: `relative_orientation_status`、`relative_orientation_count`、`relative_orientation_coverage`、`recommended_anchor_frame`、`recommended_anchor_source_pts`、`recommended_anchor_time_sec`

旧轨迹没有这些字段时仍可加载为位置轨迹，但工作台不显示推荐锚点，也不允许误判为可传播相对姿态。

## 错误处理

- 有 SRT 但解析失败：分析失败，提示 SRT 无法解析。
- SRT 时间覆盖不足：仍生成整视频单场景，但工作流预检按现有覆盖阈值阻止固定轨迹求解，并展示缺失范围。
- 没有视觉相对姿态：仅显示 SRT 轨迹，禁用姿态应用按钮。
- 推荐帧无法解码：允许用户在任意属于有效视觉段的帧建立锚点。
- 锚点不属于任何视觉段：拒绝应用并提示选择绿色姿态可用区段。
- 重复标签页或恢复状态不影响源 PTS 与轨迹的绑定。

## 测试策略

- 视频分析单元测试验证：有 SRT 的 200 秒视频只产出一个整段片段；无 SRT 的同一视频仍按现有严格时长限制分段。
- 相对姿态单元测试验证：自动世界锚定失败时仍保留连通段局部旋转和推荐帧；无视觉对时不产生伪结果。
- 对齐单元测试验证：一个人工姿态锚点传播到整个视觉段、XYZ 完全保持；第二锚点残差超过 5° 时触发分段校正。
- 静态 UI 和接口测试验证：固定轨迹面板、推荐帧跳转、单锚点门槛、无 SfM 文案和无质量阶段。
- 集成测试验证：完整 SRT 视频不生成点云，轨迹输出覆盖完整源 PTS，人工锚定后生成可渲染的连续姿态。
