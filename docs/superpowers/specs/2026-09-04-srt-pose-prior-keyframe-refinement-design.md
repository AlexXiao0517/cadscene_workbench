# SRT 位姿先验与六自由度关键帧拟合设计

## 决策摘要

完整姿态 SRT 与缺失姿态 SRT 在“基准轨迹生成”阶段采用不同实现，但生成基准轨迹后必须进入同一套关键帧微调、路线拟合、保存恢复和渲染流程。

- `srt_full_pose`：直接读取 SRT 的位置和相机/云台姿态，按权威 source PTS 映射到视频帧并转换到已确认的 CAD 米制坐标；不运行 SfM、视觉轨迹求解或姿态反算。
- `srt_fixed_track_visual_pose`：位置仍直接读取 SRT 并转换到 CAD；视觉算法只恢复姿态，不得估计或优化相机中心。
- 两条路线都把自动结果视为只读的逐帧“位姿先验”，而不是最终锁定轨迹。
- 用户可在关键帧上调整 `x/y/z/yaw/pitch/roll`；系统拟合相对于位姿先验的连续残差并生成最终逐帧路线。
- 水平 FOV 是整段视频的全局参数，可在工作台调整，但不作为逐帧关键帧量；CAD 投影、米制尺度和轴映射保持锁定。
- 渲染只消费拟合后的逐帧相机路线。原始 SRT、视觉姿态结果和人工修正分别保存，可恢复、比较和重新拟合。

该设计取代此前 `uniform_xyz_offset_only`、完整姿态锁定和固定轨迹只能统一平移的编辑规则。旧产物仍可读取，但新编辑必须迁移到残差关键帧模型。

## 目标与非目标

### 目标

1. 让 SRT 成为快速且可追溯的初始位姿来源，而不是不可修改的最终结果。
2. 复用现有 SfM 工作流中成熟的关键帧计划、相机 Gizmo、路线拟合、工作台保存/恢复和渲染交互。
3. 允许局部修正 GNSS、CAD 投影、高程基准和 SRT 姿态误差，同时保留 SRT 原始路线的局部运动细节。
4. 缺失姿态时通过视觉反算形成基准姿态；反算结束后不再维护一套独立的微调与渲染逻辑。
5. 两条 SRT 路线都不显示或启动 SfM 重建阶段，不依赖正式点云，也不进入旧质量检测流程。

### 非目标

- 不允许视觉算法反算、替换或 bundle-adjust SRT 相机中心。
- 不允许调整 CAD 坐标系、轴映射或米制比例来吸收局部轨迹误差。
- 不支持逐帧变焦、鱼眼联合标定、滚动快门或镜头畸变联合优化。
- 不要求完整姿态路线生成点云；缺失姿态路线可展示视觉算法已经产生的诊断支持点，但点云不是任务成功、拟合或渲染的必要条件。
- 不恢复旧 `srt_sfm_fused` 新建入口，也不在失败时静默回退到 `sfm_only`。

## 统一架构

整个流程拆成三层，层间通过版本化产物连接。

### 1. 不可变基准位姿层

基准轨迹保留每一帧的 source PTS、CAD 米制中心、姿态、来源和可用性：

```text
BasePose(frame) = {C_base(frame), R_base(frame), source_pts, availability}
```

- 完整 SRT 的 `C_base` 与 `R_base` 都来自 SRT。
- 缺失姿态 SRT 的 `C_base` 来自 SRT，`R_base` 来自固定中心视觉姿态求解。
- 基准轨迹文件属于 trajectory job 的不可变输出，工作台编辑不得原地修改。
- `metric_scale_locked=true`；所有位置均为 CAD local metres。

### 2. 人工关键帧残差层

用户在帧 `k` 上确认的相机状态与基准状态形成六自由度残差：

```text
delta_position(k) = C_manual(k) - C_base(k)
delta_rotation(k) = R_manual(k) * inverse(R_base(k))
```

人工文件只保存用户明确确认的关键帧及其完整相机状态、基准轨迹身份和编辑版本。自动逐帧 pose 不再伪装成人工关键帧，也不能进入已确认关键帧计数。

### 3. 连续拟合与渲染层

对每一帧 `t`：

```text
C_final(t) = C_base(t) + interpolate(delta_position, t)
R_final(t) = slerp(delta_rotation, t) * R_base(t)
```

- XYZ 残差在相邻关键帧间线性插值，避免高阶样条过冲；第一个关键帧之前保持第一个残差，最后一个关键帧之后保持最后一个残差。
- 旋转残差使用单位四元数、半球一致化和 SLERP，不直接线性插值 Euler 角。
- 关键帧处最终状态必须精确等于用户确认值。
- 没有人工关键帧时，最终路线等于基准路线。
- FOV 作为一个全局值进入每帧相机内参和视锥；修改完整 SRT 的 FOV 时可以复用已经解析的位置/姿态，只刷新基准视图、拟合和渲染产物；修改缺失姿态路线的 FOV 会使视觉姿态基准失效并重新反算。

## 完整姿态 SRT 基准轨迹

`srt_full_pose` 的自动阶段只完成：

1. 解析 SRT；
2. 用权威 frame map 将 cue/source PTS 映射到视频帧；
3. 将 WGS84 位置按已确认的 CGCS2000/CAD 配置转换为 CAD local metres；
4. 将 SRT 相机/云台姿态转换为统一 `world_from_camera` 约定；
5. 写出逐帧基准轨迹、诊断和工作台预览场景。

该阶段不得调用特征提取、匹配、COLMAP、OpenGV、三角化或 BA。工作台进度文案应为“读取 SRT 位姿”“映射视频帧”“转换到 CAD 坐标”“准备基准轨迹”，不能显示“重建”或“估计姿态”。

完整姿态覆盖不足的文件不能伪装成 `srt_full_pose`，应按能力检测进入缺失姿态路线。

## 缺失姿态 SRT 的视觉反算

`srt_fixed_track_visual_pose` 保留独立的基准姿态生成阶段：

1. 按 source PTS、运动距离与时间间隔抽取求解帧，并保留首尾有效帧；
2. 使用用户全局水平 FOV 生成固定内参；
3. 提取特征，匹配相邻帧和有限短回环；
4. 使用 SRT 已知中心之间的基线和图像对应关系估计相对旋转；
5. 构建旋转图，只优化旋转变量与必要的临时 landmark，绝不把相机中心注册为优化变量；
6. 将可靠旋转按视觉连通分量传播并插值到视频帧；
7. 输出绝对姿态、相对姿态分量、覆盖率、残差、推荐人工锚点和失败区间。

视觉算法可以在内部生成临时三维点；若这些点具备可解释坐标和稳定身份，可作为“视觉支持点”在工作台中选择性展示，但不得作为正式重建点云、不得影响 SRT 中心，也不得成为渲染前置条件。

若自动算法只能恢复相对旋转，用户在该连通分量内确认一个姿态关键帧即可完成绝对朝向锚定；多个锚点之间的旋转校正使用 SLERP。视觉分量锚点与普通修正关键帧使用明确的 `role` 区分，但第一次确认姿态可以同时完成分量锚定并成为该帧的人工修正。拟合器根据不可变相对旋转和版本化锚点生成“有效基准姿态视图”，不得改写 trajectory job 的原始产物。

如果某段既没有可靠视觉相对姿态，也没有足够的人工姿态关键帧，则该段保留位置轨迹但不生成可渲染姿态；系统不得猜测姿态或移动位置来掩盖失败。

## 工作台流程与交互

两条 SRT 工作流统一显示以下阶段：

1. `基准轨迹`：完整 SRT 显示“已读取 SRT 位置与姿态”；缺失姿态路线显示视觉姿态覆盖与诊断。
2. `关键帧微调`：生成/恢复关键帧计划，允许调整 XYZ、yaw、pitch、roll，并显示全局 FOV。
3. `路线拟合`：用人工残差生成连续逐帧路线，原始路线与拟合路线同时可见。
4. `渲染导出`：独立于微调阶段，消费最近一次已保存的拟合路线。

工作台复用现有：

- 关键帧间隔选择、首尾关键帧、继续未完成标定；
- 帧号/PTS 跳转、上一/下一关键帧；
- 平移和旋转 Gizmo、数值相机参数；
- “路线拟合”“重新路线拟合”“完成关键帧标定”；
- 草稿保存、恢复、并发修订检查和渲染入口。

SRT 模式不再显示专用的“整轨 XYZ 偏移”作为唯一编辑界面，也不再隐藏普通关键帧工具。右侧参数明确展示当前帧：`X/Y/Z/yaw/pitch/roll/FOV`、参数来源和是否为人工关键帧。

三维视图至少绘制：

- 灰色：不可变基准路线；
- 橙色：当前拟合路线；
- 当前帧相机视锥；
- 人工关键帧标记；
- 缺失姿态路线可选的视觉支持点。

播放视频时，相机视锥沿拟合路线和拟合姿态实时更新。基准姿态缺失且尚未被人工/插值补齐的帧不显示虚假视锥。

## 关键帧计划

首版直接复用现有关键帧计划交互与间隔配置，并增加以下规则：

- 首个和最后一个具备完整基准 pose 的帧必须进入计划；
- 缺失姿态路线优先加入视觉低置信、分量边界和长插值区间附近的帧；
- 已经由用户确认的关键帧保持完成状态；
- 自动轨迹中的每帧 pose 不计为人工关键帧；
- 用户可以在计划之外任意帧添加关键帧。

路线拟合允许零个、一个或多个人工关键帧：零个关键帧时显式接受基准路线；一个关键帧代表整段保持同一个六自由度残差；两个及以上关键帧才产生随时间变化的局部修正。界面应说明该差异，但不强制用户为了形式补关键帧。

## 数据与产物契约

### 基准轨迹

沿用两条 workflow 现有 trajectory 路径和 loader 主结构，新增/统一 metadata：

```json
{
  "meta": {
    "pose_prior_schema": "srt_pose_prior_v1",
    "metric_scale_locked": true,
    "position_source": "srt_cad",
    "orientation_source": "srt_full_pose_or_visual_fixed_center",
    "edit_policy": "six_dof_keyframe_residuals",
    "cad_georeference_revision": "..."
  }
}
```

### 人工轨迹

继续使用 `01_keyframes/camera_track_manual.json`，但只保存人工关键帧，并在 meta 中绑定：

- workflow；
- trajectory job ID、output revision、output fingerprint；
- source frame-map revision；
- CAD georeference revision；
- 全局 FOV 与其 revision；
- `edit_policy=srt_pose_residual_keyframes_v1`。

缺失姿态路线的关键帧还必须包含 `role=visual_component_anchor` 或 `role=pose_refinement`；同一帧可以同时承担两种角色，但持久化时仍要保留两种语义，避免重新拟合时把绝对朝向锚点误当成普通零基准修正。

### 拟合输出

继续发布渲染器已经消费的 alignment/camera-path 语义路径，避免复制一套渲染协议；同时在 metadata 和报告中明确：

- `alignment_mode=srt_pose_prior_residual`；
- `scale_observable=false`、`scale=1.0`；
- 基准位置/姿态来源；
- 人工关键帧数量；
- 最大/平均位置残差；
- 最大旋转残差；
- 最终 pose 覆盖率和不可渲染区间。

## 服务、状态与恢复

- “进入工作台”仍要求当前输入对应的基准 trajectory 已验证，但不要求已经完成关键帧拟合。
- 完整 SRT 缺少基准 trajectory 时只执行快速读取/转换任务。
- 缺失姿态 SRT 缺少基准 trajectory 时执行视觉姿态任务，并展示真实阶段进度。
- 工作台草稿绑定基准 trajectory 指纹；SRT、视频帧映射、CAD georeference 或视觉 FOV 改变后，旧草稿标记 stale，不能静默套到新基准上。
- 仅修改人工关键帧不会重跑完整 SRT 读取或视觉姿态算法，只需重新路线拟合。
- 已保存的渲染结果继续绑定具体拟合输出，重新编辑不会覆盖旧 revision。

## 旧产物迁移

旧 `uniform_xyz_offset_only` 工作台产物可只读恢复。用户首次用新版本重新编辑时：

1. 保留旧原始文件和已渲染结果；
2. 将旧 `route_offset_xyz_m` 转换为首尾两个虚拟残差关键帧；
3. 姿态残差初始化为单位旋转；
4. 用户保存后写出新的 `srt_pose_residual_keyframes_v1` revision；
5. 不原地改写旧 revision，也不把自动逐帧 pose 迁移成人工关键帧。

## 错误处理与门禁

- SRT 位置、相对高度、CAD georeference 或 frame map 不可用：阻止基准轨迹生成并显示具体原因。
- 完整 SRT 姿态覆盖不满足门槛：阻止 `srt_full_pose`，引导使用视觉姿态路线。
- 视觉姿态退化：仍发布位置轨迹和诊断，不回退 SfM；工作台可打开，但不可渲染缺失姿态区间。
- 人工关键帧包含非有限数、非法 FOV、重复帧或不属于当前基准轨迹：拒绝保存。
- 四元数无法归一化、姿态约定不一致或插值跨越无效分量：拟合失败并保留上一次成功结果。
- 最终渲染区间存在未补齐的长姿态空洞：阻止渲染并跳转到对应帧；不增加独立质量检测阶段。
- 任一输入 revision 变化：旧 trajectory、关键帧拟合和待渲染结果按依赖顺序失效。

## 实现边界

新增独立的 SRT 位姿先验残差拟合核心，例如 `cadscene/alignment/pose_prior_refinement.py`，负责：

- 校验基准 pose 与人工关键帧；
- 计算位置和旋转残差；
- 执行位置插值和四元数 SLERP；
- 生成逐帧最终路线与诊断指标。

现有 alignment CLI/JobRunner 保持外部协议不变，在检测到 `pose_prior_schema=srt_pose_prior_v1` 时调用该核心；普通 SfM、纯旋转和旧历史产物继续走原分支。这样可以复用既有工作台/渲染产物约定，又不把 SRT 语义继续堆入已经复杂的 SfM Sim3 对齐逻辑。

前端删除完整 SRT 专用的“仅统一 XYZ”行为，改为复用普通关键帧工具；缺失姿态路线保留自动姿态覆盖、推荐锚点和视觉支持点显示，但完成锚定后进入相同关键帧拟合阶段。

## TDD 验收

### 数学核心

1. 无人工关键帧时最终 pose 与基准 pose 逐帧相同。
2. 单关键帧残差在整段保持一致。
3. 两个及以上关键帧的 XYZ 残差正确插值，关键帧处精确命中人工值，区间外保持端点残差。
4. 旋转残差使用 SLERP，正确处理 `179°/-179°`、四元数正负同义和单位化。
5. FOV 与 CAD scale 不进入逐帧残差；scale 始终为 1。

### 完整姿态路线

1. `srt_full_pose` 命令不包含 SfM、特征、匹配或视觉姿态模块。
2. SRT 位置/姿态按 PTS 形成基准 pose，并可直接进入关键帧阶段。
3. 工作台可编辑 XYZ/yaw/pitch/roll，原来的 attitude/FOV/统一 XYZ 锁定校验不再阻止拟合。
4. 修改关键帧只运行 alignment，不重跑 SRT trajectory job。

### 缺失姿态路线

1. SRT 中心在视觉姿态算法前后逐帧不变。
2. 合成已知中心、已知 FOV 的图像约束能够恢复旋转到规定误差。
3. 低纹理、直线基线、重复纹理和断裂分量产生明确 partial/relative-only 状态，不产生伪姿态。
4. 一个姿态锚点可绝对锚定相对旋转分量；随后六自由度关键帧残差可继续修正该基准。
5. 视觉支持点可有可无，删除支持点不影响轨迹、拟合或渲染。

### 工作台与渲染

1. 两条 SRT 路线显示相同的关键帧计划、六自由度参数、路线拟合和独立渲染阶段。
2. 不显示“SfM 重建”“位置锁定只能统一平移”或独立质量检测。
3. 原始与拟合路线、当前帧视锥、人工关键帧同步显示并随视频 PTS 更新。
4. 保存/恢复绑定正确 trajectory revision；旧统一偏移产物可迁移且不被覆盖。
5. 渲染读取拟合后路径；关键帧变化使旧渲染 stale，但不使基准 trajectory stale。
6. 普通 `sfm_only`、`pure_rotation` 和历史 `srt_sfm_fused` 行为保持不变。

### 真实数据 smoke

使用当前 DJI 视频、CAD、合并后的完整姿态 SRT 和原始缺失姿态 SRT 分别验证：

- 完整 SRT 快速读取基准轨迹，无视觉/SfM 任务；
- 原始 SRT 执行视觉姿态反算，位置与完整路线中的 SRT 位置一致；
- 两者进入同一关键帧工作台，可分别修改局部 XYZ 与姿态并重新拟合；
- 拟合路线实时驱动视锥，保存后可以进入独立渲染；
- 重启服务后可恢复关键帧、拟合结果和工作台阶段。

## 完成定义

用户上传视频、CAD 和 SRT 后，系统根据姿态覆盖选择正确基准生成器：完整姿态直接读文件，缺失姿态运行固定中心视觉反算。基准轨迹生成后，两条路线进入同一套六自由度关键帧微调与路线拟合流程。用户能同时查看原始路线和拟合路线，逐帧播放检查相机视锥，并使用已保存的拟合结果独立渲染。任何视觉算法都不能修改 SRT 位置，任何工作流状态都不能错误显示或启动 SfM。
