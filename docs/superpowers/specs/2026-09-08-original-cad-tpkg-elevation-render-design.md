# 原始 CAD + TPKG 高程控制渲染设计

## 目标

在不修改平台正式工作流的前提下，生成一版可与 `K181合成视频.mp4` 对比的实验视频。画面主体必须来自原始 DXF/CAD，保留完整图层、实体颜色和几何；`zhix.tpkg` 与 `station.tpkg` 仅提供三维高程控制和可选站点标记，不再替代原始 CAD。

## 已确认问题

上一版仅绘制两个 TPKG 中的 7,986 条线段和 44 个点。TPKG 在部分路段没有可见路线要素，因此中后段出现主线消失；参考视频则持续绘制原始 CAD 的绿色边坡、红色横断及黄色路线等完整图层。该问题与视频解码和 XML 姿态突然失效无关。

XML 声明的是水平坐标 `EPSG:4326`，未声明垂直基准。相机 Z 应记录为“XML 空三调整后的绝对高度”，不得在报告中把它写成已经证实的椭球高。TPKG 顶点 Z 按文件原值使用，不额外叠加固定高度。

## 数据流

1. 从 Bentley XML 读取每 0.5 秒相机中心、姿态、1920×1080 内参和 Brown-Conrady 畸变参数。
2. 将 XML 相机经纬度和 TPKG 经纬度通过同一个中央经线 118°50′ 的 CGCS2000/Gauss-Krüger 投影转换到原始 CAD 局部 XY。
3. 从现有 CAD 数据集读取原始 DXF 的完整颜色与线几何，并按 XML 航迹周围 500 米裁剪，避免无关远距离实体进入投影。
4. 将 TPKG 三维折线按不大于 2 米的间隔采样，建立二维 KD 树。每个 CAD 顶点在 XY 平面查询最近的 TPKG 高程样本，并取其插值 Z，形成原始 CAD 的 XYZ 端点。
5. 对距离高程控制线过远的 CAD 点设置最大允许距离；超出范围的实体不渲染，避免把远处图框或异地 CAD 内容错误吸附到道路高程。
6. 使用 XML 相机外参、内参和畸变投影三维 CAD，保留原始实体颜色。TPKG 的站点点标记作为独立可选图层，不替代 CAD。

## 高程策略

推荐使用“最近三维路线样本的局部高程”作为首版策略。它能让整张平面 CAD 跟随道路纵断起伏，同时不会添加人为的统一高度。横向边坡和横断实体会共享附近路线里程的基准高程，这是只有线状高程控制、没有完整 DEM 时最稳定且可解释的近似。

不采用以下方案：

- 整张 CAD 固定 Z：无法适应 30 米左右的沿线地形变化。
- 直接渲染 TPKG：缺少原始 CAD 完整图层，已经证明会出现路段内容消失。
- 把 SRT 相对高当作相机 Z：相对高以起飞点为基准，不能表达当前地形高程。

## 验收与误差处理

先渲染源视频帧 300、6000、11400 三张 1080p 样片，并与参考视频同时间点比较：

- 原始绿色、红色、黄色 CAD 图层必须持续存在；
- 道路线和边坡应落在施工走廊附近，不能出现整体翻转、离地或跨路段跳变；
- 输出一份高程匹配统计，包括最近距离与相机—CAD 高差分布；
- 若仅开头存在小幅水平残差，不在本步骤引入固定高度补偿，后续由关键帧路线/姿态微调处理。

样片通过后输出源帧 300–11439、每 2 帧采样一次的 1920×1080、29.97 fps 全片，预期 5,570 帧、约 185.85 秒。

## 测试

- 单元测试验证 TPKG 折线采样保留端点和线性 Z；
- 单元测试验证 CAD 顶点使用最近高程控制样本，并拒绝超过最大距离的点；
- 单元测试验证原始 CAD BGR 颜色在高程赋值后保持不变；
- 关键帧人工检查投影方向、高程和图层连续性；
- 全片完成后使用 FFprobe 核验编码、分辨率、帧率、帧数和时长。

## 范围

本轮只生成独立实验视频和诊断报告，不把 TPKG 解析、CAD 高程贴合或相关 UI 接入平台正式流程。用户确认实验效果后，再为正式工作流单独制定实现方案。
