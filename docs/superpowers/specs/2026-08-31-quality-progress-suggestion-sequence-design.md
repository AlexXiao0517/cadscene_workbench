# 质量检测真实进度与建议帧顺序浏览设计

## 目标

修复工作台质量检测长期停在 5% 后突然完成的问题，并把建议帧浏览改成按视频时间从前到后、末尾循环到开头的稳定顺序。

## 质量检测进度

- 进度来源必须是后端实际工作量或真实子阶段，不使用计时器模拟。
- `JobRunner` 为质量任务创建独立进度 sidecar，并把 sidecar 中的阶段、消息和 fraction 持续同步到现有 `job_status.json`。
- `run_pipeline` 负责报告质量任务的真实子阶段边界：输入校验、质量评估、质量产物写入、Viewer 场景导出、道路表面诊断和最终验证。
- `evaluate_quality` 在遍历权威相机路径帧时按 `processed / total` 报告进度；该区间映射到质量任务总进度的 10%～45%。
- 质量产物写完到 55%，Viewer 场景完成到 75%，道路表面诊断完成或明确跳过到 95%，仅父进程确认命令成功后写 100%。
- 进度必须单调不回退；刷新页面后继续从 `job_status.json` 读取当前状态。
- 失败和取消沿用现有契约，不允许提前显示 100%。

## 建议帧顺序

- 后端仍按风险选择建议帧，不改变建议算法和阈值。
- 浏览器加载后按 `frame_index` 升序生成可浏览序列，不再按风险分数重排展示顺序。
- 第一次点击跳到最早建议帧，之后每次点击跳到下一帧，最后一帧之后循环回第一帧。
- 忽略当前建议后，从时间上紧随其后的可用建议继续；若被忽略的是最后一帧，则循环到第一帧。
- 按钮显示下一次将查看的序号和总数，例如“查看下一建议帧（3/9）”。
- 质量建议重新加载时，如果当前选择仍存在则保持游标；否则从最早可用建议重新开始。

## 代码边界

- 新增一个无 DOM 依赖的建议序列模块，负责排序、循环和忽略后的游标选择，`workflow.js` 只负责 UI 与视频跳转。
- 质量算法只接受可选进度回调，不耦合 HTTP 或前端状态。
- sidecar 继续使用原子 JSON 写入；`JobRunner` 是把子进度发布到工作流状态的唯一父进程边界。

## 测试与发布

- TDD 覆盖帧级进度、子阶段里程碑、sidecar 到 `job_status` 的同步、单调性、失败不完成、建议帧升序循环及忽略行为。
- 运行工作流、Viewer 静态契约和全量回归。
- 验证通过后快进或合并到 `main` 并推送。
- 使用合入后的 main 重新构建 0.1.2 全装包，执行包内 doctor、首次迁移、服务启动和质量进度资源检查，更新 ZIP SHA-256。
- 不包含或修改“向上/向下打通”功能。
