# 未完成路线与相邻打通状态修复设计

## 问题

工作台允许用户在尚未路线拟合时保存关键帧，这是必须保留的能力。但现有相邻路线打通把任意 `saved` 工作台输出都当作“完整路线”，导致仅含一个默认关键帧的片段既被错误显示为打通源片段，又阻止上一片段重新打通它。若目标已有这类存档，工作台恢复还会优先加载旧存档而不是新生成的 scene bridge。

## 完整路线判定

SfM 工作台输出只有同时满足以下条件才可作为相邻打通源路线：

- immutable workbench output 校验通过；
- 相机轨迹中至少包含两个 `confirmed_keyframes` 认可的人工锚点。

单关键帧或仅默认预览相机仍可保存、退出和恢复，但不代表路线拟合完成。

## 状态规则

- 未完成路线不能显示向上/向下打通，API 直接提交也必须拒绝。
- 目标片段只有未完成存档时，不阻止相邻完整路线对其发起打通。
- active editing 或 pending save 仍阻止覆盖。
- 目标已有完整保存路线时仍阻止覆盖。
- scene bridge 成功后，匹配的旧未完成 workbench 引用标记为 stale；immutable 旧输出保留。
- 打开目标工作台时，有有效 scene bridge 就优先恢复 scene bridge，不恢复旧的未完成 baseline。
- 用户完成微调并再次保存后，新 workbench 输出重新成为 active saved 结果。

## 测试

- 单关键帧存档保持可恢复，但不能成为打通源。
- 上一完整片段仍可向下打通这个未完成目标。
- scene bridge 成功后旧未完成引用变 stale，打开工作台加载 bridge seed。
- 已完成路线、活动会话、重复打通和恢复逻辑保持现有行为。
