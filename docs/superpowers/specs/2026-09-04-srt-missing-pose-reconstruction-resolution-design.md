# 缺失姿态 SRT 解算分辨率设计

## 目标

为 `srt_fixed_track_visual_pose`（SRT 有完整位置但缺失姿态）增加可选的姿态解算分辨率，减少 4K 抽帧、写盘、读取和 COLMAP 特征计算耗时。该设置不得改变 SRT→CAD 轨迹、源视频、工作台预览或最终渲染分辨率。

## 已确认的产品行为

- 配置项只在缺失姿态 SRT 场景显示，完整姿态 SRT 不显示。
- 选项为：
  - `1080p（推荐）`，默认值；
  - `720p（快速）`；
  - `原始分辨率`。
- DJI 视频按横屏处理；缩放时保持宽高比并保证输出宽高为偶数。
- 源视频高度小于所选高度时不放大。
- 水平 FOV 仍由用户输入整数；系统按实际解算图像宽度重新计算 `fx/fy/cx/cy`。
- 解算完成后，轨迹中心继续严格采用 SRT→CAD；COLMAP 只提供姿态和可选稀疏点云。
- 后续六自由度关键帧微调、路线拟合、保存和独立渲染流程不变。

## 方案选择

采用“抽帧时直接缩放”。它比仅设置 COLMAP `max_image_size` 多消除了全尺寸 PNG 的写盘和读取成本；相比先生成代理视频，不引入额外转码文件和 PTS 映射风险。

不采用：

- 仅调整 `max_image_size`：COLMAP 会缩小特征图像，但仍需生成和读取 4K 抽帧。
- 代理视频转码：增加一次完整转码，并扩大 SRT/视频时间轴不一致的风险面。

## 数据与接口

缺失姿态配置新增稳定枚举字段：

```json
{
  "horizontal_fov_deg": 60,
  "reconstruction_resolution": "1080p",
  "route_offset_xyz_m": [0.0, 0.0, 0.0]
}
```

允许值为 `720p`、`1080p`、`source`。旧项目缺少该字段时按 `1080p` 解释。非法值在保存配置和准备任务时均拒绝。

适配器根据源视频尺寸和枚举计算目标尺寸，并把目标高度传给 `run_sfm`。`run_sfm` 在抽帧阶段完成等比例缩放；相机 PINHOLE 参数使用目标宽高和用户 FOV 计算。任务身份包含该枚举，修改分辨率会生成新的轨迹任务；适配器版本随之提升，避免复用旧结果。

缺失姿态任务默认请求 `device=auto`：检测到本地 CUDA COLMAP 时使用 GPU，否则明确记录 CPU 回退，但不改变算法。

## 状态与诊断

任务进度和报告记录：

- 用户选择值；
- 源视频尺寸；
- 实际解算尺寸；
- 水平 FOV 和换算后的 PINHOLE 参数；
- COLMAP 后端及 CPU/CUDA 设备。

工作台只显示实际采用的解算参数，不把解算分辨率误认为渲染分辨率。

## 错误处理

- 无法获得源视频宽高：任务准备失败并给出明确错误。
- 非法分辨率枚举：配置接口返回校验错误，不入队。
- 缩放失败或生成空帧：SfM 阶段失败，保留 attempt 日志以便重试。
- CUDA 不可用：自动回退 CPU，并在进度与报告中标注，不回退到 OpenCV 姿态算法。

## 测试策略

- 项目设置：默认值、三种合法值、非法值、保存与恢复。
- 条件 UI：只对 `srt_fixed_track_visual_pose` 展示选择框。
- 尺寸计算：4K→1080p、4K→720p、小尺寸不放大、偶数尺寸。
- 相机参数：目标宽度变化时焦距与主点同步缩放，FOV 保持不变。
- 命令契约：缺失姿态任务传入缩放参数和 `device=auto`；完整姿态任务不运行 COLMAP。
- 回归：SRT 位置保持不变，姿态来自 COLMAP，最终渲染仍使用原视频。
