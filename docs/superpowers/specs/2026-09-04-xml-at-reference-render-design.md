# XML 空三基准渲染设计

## 目标

生成一支可与 `K181合成视频.mp4` 直接比较的 1080p 后端视频，用来验证空三优化外参、精确相机内参和镜头畸变对 CAD 投影精度的贡献。该视频是诊断基准，不改变平台现有 SRT 工作流或项目保存状态。

## 输入与时间范围

- 视频：项目 `p-4fa71cfb477a488e` 的原始准备视频，3840×2160、约 59.94 fps。
- CAD：当前项目已确认的 CGCS2000 / 118°50′ CAD 数据。
- 空三结果：`C:/Users/Hanshark/Desktop/1080p Block - 0.5秒.xml`。
- 参考区间：源视频约 5.0–190.85 秒，对应源帧约 300–11439；输出约 185.85 秒。
- 输出：1920×1080、H.264，可在浏览器或本地播放器中直接播放。

## 相机外参

每个 XML `Photo` 使用 `Pose/Center` 作为空三优化后的 WGS84 相机中心，使用 `Pose/Rotation` 的 Yaw、Pitch、Roll 作为相机姿态。XML 锚点由文件名中的 `frame_NNNNNN` 映射到原始视频帧；相邻 30 帧锚点之间：

- 位置在 WGS84 地心坐标中线性插值，再投影到已确认的 CGCS2000 高斯—克吕格坐标；
- 姿态使用最短弧四元数球面插值；
- 高程使用 XML 优化绝对高程，并减去原始 SRT 的 `abs_alt - rel_alt` 基准，使 CAD 二维平面继续位于本地 `z=0`。

本基准不使用 SRT 经纬度覆盖 XML 优化中心。SRT 只提供原始视频高程基准和数据血缘验证。

## 相机内参与畸变

从 XML `Photogroup` 读取：

- 焦距 `14.9438489018156 mm`；
- 传感器宽度 `17.3 mm`，得到水平 FOV 约 `60.127390°`；
- 主点 `(954.7604808, 519.6846123)`；
- 径向畸变 `K1=-0.0124025935`、`K2=0.0171692916`、`K3=0.0449273883`；
- 切向畸变 `P1=0`、`P2=0`；
- 像素纵横比 `1`、斜切 `0`。

投影先在归一化相机坐标中应用 Brown–Conrady 径向/切向畸变，再使用 XML 焦距和主点转换成 1920×1080 像素坐标。若 XML 参数缺失、非有限或相机模型不是 Perspective，渲染应明确失败，不回退到用户 FOV。

## CAD 投影与输出

沿用现有 CAD 坐标转换、相机旋转约定、近裁面、距离淡出和颜色叠加逻辑。为控制诊断视频耗时，可批量投影静态 CAD 线段并按固定间隔采样视频帧，但必须保持：

- 参考区间的真实播放时长；
- XML 外参对应的原始源帧索引；
- 1920×1080 输出尺寸；
- H.264 / yuv420p 播放兼容性。

采样帧率属于诊断输出元数据，不能伪称原始 59.94 fps 姿态精度。

## 验证

1. 单帧检查源帧 300、约 6000 和约 11400，确认底层画面与参考视频的 0 秒、中段和末段一致。
2. 检查 XML 锚点帧的投影使用 `Pose/Center`，而不是 `Metadata/Center` 或 SRT GPS。
3. 用独立计算验证 XML FOV、主点和畸变系数进入投影。
4. 对成片执行完整 FFmpeg 解码，并用 ffprobe 核对分辨率、时长、编码、像素格式和帧数。
5. 抽取至少三个时刻与参考成片同场景比较，记录仍存在的几何偏差，不把视觉接近直接表述为算法等价。

## 平台后续讨论边界

本次输出只验证“完整 XML 空三结果作为真值输入”的上限。平台正式方案仍以视频、CAD 和 SRT 为输入；是否使用 COLMAP 恢复相同级别的相机中心、姿态、内参和畸变，需要根据本次对比结果单独设计，不能让诊断 XML 成为生产必需输入。
