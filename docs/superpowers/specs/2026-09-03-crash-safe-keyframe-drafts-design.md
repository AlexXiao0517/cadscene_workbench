# 关键帧微调草稿的崩溃恢复设计

## 目标

用户确认过的关键帧调整不能只存在浏览器内。服务意外退出、浏览器刷新或重新进入工作台后，应恢复最近一次已确认调整；单纯拖动虚拟相机但未点击确认的变化仍视为临时预览。

## 状态边界

- **临时预览**：仅改变当前浏览器中的相机，不写盘，离开前提示存在未保存更改。
- **服务器草稿**：点击“添加/更新关键帧”“保存微调关键帧”、接受建议帧或删除关键帧后，完整相机轨迹以项目级草稿原子写盘。
- **正式成果**：点击“保存并返回”后，将最新兼容草稿提升为不可变 workbench output，并保留其来源关系。

草稿单独存放在 `projects/<project_id>/workbench_drafts/<clip_id>.json`，不写入 clips/jobs manifest。它包含独立 revision、operation_id、输入与轨迹绑定、完整 camera track、更新时间及可选的 promoted output revision。

## 一致性规则

1. 草稿必须同时绑定 project/clip、clip input revision、workflow、trajectory output revision/fingerprint。
2. 任一绑定变化后旧草稿不可自动恢复，避免把关键帧应用到另一版视频、分段或轨迹。
3. 草稿使用 `expected_revision` 和 `operation_id`，并通过临时文件 + replace 原子发布。
4. 打开工作台时，兼容且未提升的草稿优先于上一次正式成果/场景打通种子恢复到当前 run。
5. 保存正式成果前再次把草稿写回 run，确保不可变输出与用户最后确认的草稿一致；成功后标记草稿已提升。
6. 旧项目没有草稿文件时继续按原有逻辑恢复，不迁移或改写已有成果。

## 前端交互

确认关键帧的按钮在本地轨迹完成更新后调用项目工作台草稿 API。成功后显示“微调已保存到服务器”；失败时保留脏状态并明确提示，不能假装已保存。普通相机拖动只设置浏览器未确认状态，不触发网络写入。

## 服务停止保护

停止脚本在终止服务前查询/检测仍处于 editing 的工作台会话并显示警告；交互式启动器要求再次确认。该保护用于提醒未确认的浏览器移动仍可能丢失，已经形成服务器草稿的关键帧不受服务重启影响。

## 非目标

- 不持续保存每一次相机鼠标移动；
- 不改变 SfM、路线拟合或场景打通数学；
- 不把草稿计入正式片段完成度；
- 不为草稿复制视频、CAD、SfM 或渲染大文件。
