# 同机 Workspace 升级兼容设计

## 目标

让测试人员在同一台 Windows 电脑上，把旧版整合包的整个 `workspace` 复制到新版整合包后，仍能恢复项目、关键帧、轨迹、质量检测和渲染进度。迁移不得重写既有 manifest，也不得改变已经参与 revision/fingerprint 计算的绝对路径。

## 方案

新版启动器在环境检查和服务启动之前调用独立的 Python 检查器：

1. 只扫描新 `workspace` 内的 JSON 文件，从绝对路径值中识别旧 `workspace` 根目录；
2. 仅接受一个旧根目录，并校验新副本包含旧项目清单及所有仍存在的被引用文件；
3. 如果旧根目录仍是普通目录，先确认没有 CADScene 进程使用它，再将其改名为带时间戳的可恢复备份；
4. 在旧根目录原位置创建指向新 `workspace` 的 Windows Junction；
5. 写入迁移标记，后续启动只校验 Junction 仍指向当前副本；
6. 任一步失败都停止启动并给出中文处理提示；创建 Junction 失败时自动把备份恢复到原路径。

这样旧 manifest 中的绝对路径仍然可访问，历史 fingerprint 不变；新数据仍写入新包的 `workspace`。迁移仅支持同机 Windows 升级，不承诺跨电脑恢复。

## 安全边界

- 不删除旧工作空间；原目录改名为同目录备份。
- 不重写 JSON、SQLite、媒体文件或算法输出。
- 多个旧根目录、缺失项目清单、缺失仍被引用的物理文件、旧服务仍运行时均拒绝迁移。
- 只允许处理名称为 `workspace` 且包含 `projects`、`data` 或 `runs` 结构的绝对路径。
- 已迁移状态必须幂等：Junction 正确时不再移动目录，Junction 错误或失效时拒绝启动。

## 验收

- 复制 0.1.0 `workspace` 到 0.1.3 后，首次启动建立兼容 Junction 并保留旧目录备份。
- 刷新或再次启动不会重复迁移。
- 旧关键帧、轨迹、质量和渲染状态可由原绝对路径正常读取。
- 不完整副本、混合多个旧包、旧服务仍运行或 Junction 被篡改时给出明确错误。
