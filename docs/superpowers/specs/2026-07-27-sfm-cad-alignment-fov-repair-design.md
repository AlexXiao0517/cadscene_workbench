# SfM–CAD 对齐与 FOV 防退化最小修复设计

日期：2026-07-27

## 目标

修复当前路线拟合中“相机路线被锚点拉回 CAD，但点云仍沿错误全局 Sim3 倾斜”的问题，并阻止病态 SfM 内参把人工确认的 67° 水平视场角覆盖为 28.414°。

本轮只重跑 alignment 与 viewer scene，不重跑 SfM。现有 SfM 点云可能包含由病态内参造成的非相似形变，本轮不承诺消除这部分上游误差。

## 已确认根因

1. SfM 输出的 OPENCV 内参为 `fx=3791.91`、`fy=410.44`，比例约 9.24，明显不符合方形像素相机。28.414° 是由异常 `fx` 计算得到的水平 FOV。
2. 两个人工锚点均保存了 67°，路线生成却配置为优先使用 SfM trajectory，因此算法预测帧被写成 28.414°。
3. 当前全局 Sim3 的旋转完全由人工姿态平均得到，只用锚点距离确定尺度，没有强制 SfM 基线方向映射到 CAD 基线方向。
4. 当前两个 CAD 锚点等高，但全局 Sim3 把对应基线抬升约 105.35 米，两个端点各产生约 54.15 米残差。
5. 分段锚定只修正相机路径；静态点云继续使用全局 Sim3，因此路线与点云采用了不一致的空间映射。

## 修复范围

### 两锚点全局旋转

当只有两个非重合锚点时：

- 尺度继续由两条基线长度之比确定。
- 全局旋转必须精确把 SfM 基线方向映射到 CAD 基线方向。
- 绕目标基线仍未确定的 twist，仅使用两帧人工相机姿态选择与姿态约束最接近的解。
- 平移由锚点中心确定。

三点及以上的通用求解保持现有接口，本轮不扩展成新的全局优化器。

### FOV 来源

- 如果已确认人工关键帧具有一致、有效的 FOV，则整个预测路线使用该人工 FOV。
- 只有没有可用人工 FOV 时，才回退到 trajectory FOV 或配置默认值。
- 当前 run 应统一输出水平 FOV 67°。

### 失败保护

alignment 结果导出前检查：

- 全局锚点位置残差必须低于明确阈值。
- 两锚点映射后的基线方向误差必须低于明确阈值。
- trajectory 内参出现非有限数、非正焦距或严重 `fx/fy` 失衡时，标记为病态，不允许它覆盖人工 FOV；若已有一致人工 FOV，可继续路线拟合并携带警告，否则停止导出。

失败时返回可读错误，不再生成表面成功但点云与路线分离的 viewer scene。

## 数据流

1. 读取人工关键帧与 SfM trajectory。
2. 选择可信 FOV：人工一致值优先。
3. 估计满足锚点基线约束的全局 Sim3。
4. 验证全局残差和基线方向。
5. 生成相机路径及预测关键帧。
6. 点云与 global track 使用同一全局 Sim3。
7. 重新导出 viewer scene，检查点云主平面、锚点残差和 FOV 连续性。

## 测试与验收

先添加会在当前实现上失败的回归测试，再写最小实现。

自动化验收：

- 两锚点且姿态与位置冲突时，估计结果仍精确映射基线方向。
- 两个锚点的全局位置残差接近零，不再出现约 54 米误差。
- 两个人工锚点均为 67°时，所有预测帧都为 67°。
- 病态 `fx/fy` 不得覆盖人工 FOV。
- 现有三锚点、纯旋转和坐标约定测试继续通过。

当前数据验收：

- 重跑后两个全局锚点位置残差显著低于当前 54.15 米。
- 映射后基线高程差接近 CAD 目标的 0 米。
- `camera_track_pred.json` 与 `sfm_camera_path.csv` 不再混用 28.414°和 67°。
- 前端场景中 global track 与 anchored route 不再出现由 105.35 米错误基线高差造成的分离。
- 点云平面不得被宣称已与 CAD 共面；反事实计算表明，仅修复两锚点基线后，点云局部主平面预计仍会倾斜约 27–29°，界面和报告必须保留上游 SfM 几何不可靠的警告。

## 后续但不属于本轮

若点云仍有明显非刚性形变，使用水平 FOV 67°对应的约 `fx=fy=1450`，采用单焦距或受约束相机模型重新执行 SfM，并增加至少第三个空间分散的人工锚点。
