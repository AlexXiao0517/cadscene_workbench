# 关键帧微调草稿实施计划

1. 先为原子草稿仓库补充失败测试：创建、expected_revision 冲突、输入绑定和提升状态。
2. 为项目工作台 API 补充失败测试：确认轨迹写入草稿、重启/重开恢复、正式保存提升、输入变化忽略旧草稿、旧项目兼容。
3. 实现 `AtomicWorkbenchDraftStore`，接入 `ProjectWorkbenchService` 和 HTTP `draft` action。
4. 为工作台前端补充失败静态测试，覆盖四类明确确认动作、成功/失败状态与仅拖动不自动写盘。
5. 接入确认动作的草稿保存；保持旧的非项目工作台保存路径。
6. 为 Windows 停止脚本补充活动编辑会话提示测试并实现最小保护。
7. 运行项目、viewer、打包聚焦测试，再运行全量测试、依赖检查和 `git diff --check`。

本次不重启当前 8300 服务；代码验证完成后再由用户决定何时同步整合包和重启。
