# 后台并发、渲染发布、旋转进度与场景定位实施计划

> 按 TDD 顺序执行，每个行为先出现可复现失败，再做最小实现。

## 1. 运行时资源并发

- 在 `tests/projects/test_runtime.py` 增加多个已调度资源任务可并发执行、关闭时完整回收的测试。
- 将 `ProjectRuntime` 从单 worker 改为受资源容量约束的 worker 集合。
- 增加同项目输入变化后旧任务不发布的回归覆盖。

## 2. 渲染不可变发布身份

- 在 `tests/projects/test_render_jobs.py` 重现不同任务/输入产生相同适配器输出 revision 的碰撞。
- 在服务端验证完成后派生项目发布 revision，保留旧清单读取兼容。
- 验证同任务重试幂等、篡改检测和 frame map 契约不变。

## 3. 纯旋转真实合并进度

- 为后端 stdout 流式进度、CLI 进度转换和管理快照单调合成分别增加失败测试。
- 为 `ExternalOpenGVBackend.run_video` 增加进度回调，解析实际处理帧。
- 从权威 frame map 传入总帧数；把依赖导出和主任务映射为一条整体进度。
- 增加前端契约测试，确保管理界面不自行重置进度。

## 4. 同场景相邻片段定位

- 在 workbench session/service 测试中覆盖上下方向、同场景限制、边界帧、不可变来源、活动/已保存目标拒绝覆盖。
- 增加定位种子模型、原子持久化、API 和管理快照能力。
- 在项目片段行增加“向上定位/向下定位”，成功后打开目标工作台。
- 工作台加载种子后跳到目标边界帧，并将继承位姿识别为可用于路线拟合的场景边界锚点。

## 5. 验证与提交

- 运行聚焦测试、静态前端契约、`git diff --check`。
- 运行无项目依赖检查和全量 pytest。
- 使用真实多片段项目验证上下定位、纯旋转进度和渲染发布。
- 分阶段提交，不合并 main，等待人工验收。
